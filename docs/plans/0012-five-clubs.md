# Plan 0012: Five more clubs in clubs.json (four former Primera clubs and Independiente Rivadavia)

Related ADRs: [0003](../adr/0003-data-sources.md) (sources), [0005](../adr/0005-no-official-crests.md) (generic crests), [0009](../adr/0009-data-model-naming.md) (field names), [0012](../adr/0012-club-identity-aliases-colors.md) (ids, aliases, color semantics, contrast), [0013](../adr/0013-club-theming-and-onboarding-storage.md) (club theming), [0015](../adr/0015-ingestion-adapter-contract.md) (unknown clubs stop the ingestion), **[0016](../adr/0016-club-dataset-scope-and-single-color-clubs.md)** (new, Proposed: dataset scope, single-color clubs, `celeste claro`).

Record rules, the two-source verification method, the color mapping and the contrast rules are those of [plan 0007](0007-clubs-dataset.md) and ADR 0012; this plan does not repeat them.

## Delivery: two independent parts

- **Part A, issue #60 (p0):** Arsenal de Sarandí, Colón de Santa Fe, Patronato de Paraná, San Martín de Tucumán. Shippable alone, does not depend on any answer about Independiente Rivadavia. PR "Closes #60".
- **Part B, issue #48 (p2):** Independiente Rivadavia. Starts only after Diego answers D1. PR "Closes #48". Part B is written so it can go before or after Part A; the tasks note the two counts that differ.

## Goal

Add the five clubs that the openfootball files 2018-19 to 2025 name and `data/clubs.json` lacks, so `pnpm data:ingest openfootball` resolves every team name and issue #8 can commit real matches, with the same verified facts, aliases and contrast guarantees as the 29 clubs of plan 0007.

## Acceptance criteria

### Issue #60 (copied)

- Given the four clubs, when `data/clubs.json` is validated, then each has a stable slug id, display name, short name (at most 15 characters), aliases covering every source spelling, colors, jersey pattern, official founding year, city and a `source`.
- Given the facts of each club (founding year, city, colors, pattern), when they are recorded, then each is backed by two independent sources, following plan 0007 and ADR 0012, and the verification log lists them.
- Given the openfootball spellings ("Arsenal de Sarandí", "Colón de Santa Fe", "Patronato de Paraná", "San Martín de Tucumán") and the Kaggle spellings, when the resolver runs, then each maps to its club and lookalike names do not resolve.
- Given the clubs are added, when the clubs dataset tests and the alias-uniqueness check run, then they pass (aliases unique after folding, contrast rules of ADR 0012 met).
- Given the real `data/clubs.json`, when `pnpm data:ingest openfootball --dry-run` runs against the pinned files, then no club other than Independiente Rivadavia (#48) is reported as unknown.

Out of scope (#60): Independiente Rivadavia and any other club; committing matches (#8).

### Issue #48 (copied)

- Given the club needs a second color, when a verified second color exists, then it is documented with sources in data/clubs.json and the club is added.
- Given no verified second color exists, when the model is changed to make `colors.secondary` optional, then the schema, the validator, a database migration (with parity tests) and the palette contrast tests all handle the missing value, and the club is added.
- Given the club is added, when the clubs dataset test runs, then the PENDING_CLUB_IDS list is empty.
- Given the openfootball name and the Kaggle name "Independiente Rivadavia", when the resolver runs, then both map to the club.
- Given the lookalike name "Independiente Riv", when the resolver runs, then it does not resolve to Independiente Rivadavia.

Out of scope (#48): any other club; redesigning club theming beyond an optional secondary color.

Note on the fourth criterion of #48: the Kaggle spelling is `Ind Rivadavia` (already in `tests/fixtures/clubs/source-names.ts`), and `Independiente Rivadavia` is the openfootball spelling. Both become aliases.

## Approach

1. **Fixtures first.** Add a `FORMER_CLUB_ROWS` list (id, openfootball, kaggle) next to `CLUB_SOURCE_ROWS` in `tests/fixtures/clubs/source-names.ts`; `CLUB_SOURCE_ROWS` stays the 30 clubs of 2025. `KAGGLE_CLUB_NAMES` is built from both lists (29 + 4 = 33 names), so `scripts/check-club-aliases.ts` checks the former clubs too with no code change. Move `San Martin (T)` out of `KAGGLE_LOOKALIKE_NAMES`. Add `NEAR_MISS_NAMES` (strings that no source uses and that must not resolve).
2. **Dataset contract.** `clubs-dataset.test.ts` expects the 2025 clubs minus `PENDING_CLUB_IDS` plus the former clubs, resolves both spellings of each, and pins the founding year and pattern of the new clubs (the facts most likely to be "corrected" by mistake).
3. **Palette.** Add `celeste claro` to `src/data-model/club-palette.ts` (test first).
4. **Ingestion tests follow the data.** The openfootball tests build their club list from the real `clubs.json` plus synthetic records for the missing names. When a real club is added, its synthetic record must go (the synthetic ids differ from the real ones, and the same alias would then exist twice in `FIXTURE_CLUBS`). The expected unknown-name lists shrink to `Independiente Rivadavia` (Part A) and to nothing (Part B). After Part B no real name is unknown, so the "unknown club" tests switch to a `clubs.json` with one club removed.
5. **UI counts.** The pinned counts (29) in `club-catalog.test.ts`, `club-theme-contrast.test.ts` and `tests/e2e/onboarding.spec.ts` become 33 (Part A) and 34 (Part B). Copy change per D2.
6. **Data last.** Records go in only after the tests above are red for the right reason, and each record's facts are rechecked against the permalinks in the verification log.

No change to `src/data-model/schemas.ts`, the validator, Supabase migrations, `club-catalog.server.ts`, `club-options.ts`, `club-theme.ts` or the crest: they already handle any number of clubs.

## Discarded alternatives

- **Synthetic former clubs only in tests (do nothing in `data/`):** #8 could not commit any real match. Rejected.
- **Hide former clubs from the onboarding:** needs a new schema field (`active`) or a hard-coded list, and leaves their fans out. Rejected (D2 recommendation).
- **Fuzzy or accent-insensitive matching for `Colon` / `Colón`:** forbidden by ADR 0012; both spellings are aliases instead.
- **Ids from the openfootball spelling** (`arsenal-de-sarandi`, `colon-de-santa-fe`, as in the test-only synthetic records): against the ADR 0012 rule and inconsistent with `union`, `belgrano`, `instituto`. Rejected (D3 offers `arsenal-sarandi` as the only reasonable variant).
- **Base celeste for Arsenal with a contrast exception:** the crest rule exists so the sash is visible; a shade is the documented way out. Rejected.
- **Using the crest or kit templates (`body1 = 27BEF8`, `000040`) as color sources:** brand material and editor renderings (ADR 0005, ADR 0012 decision 6). Rejected; they were only read to notice which facts to look for.
- **Optional `secondary` for Independiente Rivadavia:** see D1, option A.
- **One PR for both issues:** #60 is p0 and must not wait for D1. Rejected.
